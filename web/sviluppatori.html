Panoramica

Un'API REST in JSON, in sola lettura. Il catalogo è pubblico; i dati del tuo conto chiedono una chiave.

URL di base
https://example.com/api/v1
  • Gli importi sono in centesimi di euro: 39000 vuol dire 390,00 €.
  • Le quote e le percentuali sono frazioni: 0.15 vuol dire 15%.
  • Le date sono in UTC.
  • I messaggi d'errore arrivano nella lingua dell'intestazione Accept-Language (italiano o inglese).
OpenAPI 3.1. La descrizione completa, per Postman, i generatori di client e gli agenti AI: /api/v1/openapi.json

Autenticazione

Crea una chiave nella tua area, sezione Sviluppatori. La chiave comincia con ak_ e si vede una volta sola: conservala come una password.

Mandala in ogni richiesta privata, nell'intestazione Authorization:

curl https://example.com/api/v1/io \
  -H "Authorization: Bearer ak_la_tua_chiave"
{
  "dati": {
    "nome": "Leo Ferri",
    "codice": "leo-ferri-ywni",
    "github": null,
    "zona": "Bergamo e provincia",
    "email": "leo@example.com"
  },
  "pagina": 1
}

Puoi avere fino a 10 chiavi attive e revocarle quando vuoi. Una chiave revocata smette di funzionare subito.

Paginazione

Le liste del conto (vendite, quote, notifiche) danno 100 elementi per pagina. Chiedi la pagina successiva con il parametro pagina, finché ne ricevi meno di 100.

curl "https://example.com/api/v1/vendite?pagina=2" \
  -H "Authorization: Bearer ak_la_tua_chiave"

Il catalogo dà 24 prodotti per pagina e dice quante pagine ci sono in tutto, nei campi totale e pagine.

Limiti, errori e CORS

  • Al massimo 120 richieste al minuto per chiave. Oltre, la risposta è 429: aspetta un minuto e riprova.
  • Gli errori hanno un codice HTTP e un corpo JSON con il campo errore.
  • L'API accetta richieste da qualunque origine (CORS aperto, solo GET): puoi chiamarla anche dal browser. Non mettere mai la chiave in una pagina pubblica.
CodiceQuando
401La chiave manca, non è valida o è stata revocata.
403Il conto è sospeso.
404La risorsa o il prodotto non esistono.
429Più di 120 richieste in un minuto.
 
{ "errore": "Chiave non valida o revocata" }

Webhook

Aggiungi un indirizzo https nella tua area, sezione Integrazioni, e scegli gli eventi (o tutti). Ti mostriamo il segreto una volta sola: comincia con whsec_ e serve a verificare la firma.

A ogni evento mandiamo una richiesta POST con queste intestazioni:

POST /il-tuo-webhook HTTP/1.1
Content-Type: application/json
User-Agent: {{NOME}}-Webhook/1
X-Evento: vendita.nuova
X-Firma: t=1760174691,v1=5f2b…c9e1

Il corpo è sempre lo stesso involucro: un id unico, il tipo, la data e i dati dell'evento.

{
  "id": "evt_3kQ9xV2mT0aLr8pB",
  "tipo": "vendita.nuova",
  "creato": "2026-10-11T09:24:51.112Z",
  "dati": {
    "prodotto": "Pannello di Controllo",
    "importo": 7294,
    "ruolo": "installatore",
    "cliente": "Panificio Gatti"
  }
}

Un tentativo ripetuto ha lo stesso id: usalo per non elaborare due volte lo stesso evento. Dalla tua area puoi mandare un evento di prova quando vuoi.

Negli eventi sugli accordi, quota è la parte di chi vende e resto quella di chi sviluppa, in percentuale intera: 20 e 80 vogliono dire 20% e 80%. Verificare la firma

L'intestazione X-Firma contiene il momento della firma (t, in secondi) e la firma (v1): un HMAC-SHA256 in esadecimale del testo t, un punto e il corpo così come arriva, calcolato con il tuo segreto.

Calcola la stessa firma, confrontala in tempo costante e scarta le richieste più vecchie di cinque minuti.

Node.js

verifica.mjs
import { createHmac, timingSafeEqual } from 'node:crypto';
import { createServer } from 'node:http';

export function verifica(corpo, intestazione, segreto, tolleranza = 300) {
  const parti = Object.fromEntries(intestazione.split(',').map(x => x.split('=')));
  const t = Number(parti.t);
  if (!t || Math.abs(Date.now() / 1000 - t) > tolleranza) return false;
  const attesa = createHmac('sha256', segreto).update(`${t}.${corpo}`).digest('hex');
  const a = Buffer.from(attesa), b = Buffer.from(parti.v1 || '');
  return a.length === b.length && timingSafeEqual(a, b);
}

createServer(async (req, res) => {
  let corpo = '';
  for await (const pezzo of req) corpo += pezzo;
  if (!verifica(corpo, req.headers['x-firma'] || '', process.env.SEGRETO_WEBHOOK)) {
    res.writeHead(400);
    return res.end();
  }
  const evento = JSON.parse(corpo);
  console.log(evento.tipo, evento.dati);
  res.writeHead(200);
  res.end('ok');
}).listen(3000);

Python

verifica.py
import hashlib
import hmac
import time


def verifica(corpo: bytes, intestazione: str, segreto: str, tolleranza: int = 300) -> bool:
    parti = dict(x.split("=", 1) for x in intestazione.split(",") if "=" in x)
    t = int(parti.get("t", "0") or 0)
    if not t or abs(time.time() - t) > tolleranza:
        return False
    attesa = hmac.new(segreto.encode(), f"{t}.".encode() + corpo, hashlib.sha256).hexdigest()
    return hmac.compare_digest(attesa, parti.get("v1", ""))

Tentativi ripetuti

Una consegna riesce quando il tuo server risponde con un codice 2xx entro 10 secondi. I redirect non si seguono.

Se non riesce, riproviamo con attese sempre più lunghe: dopo 1 minuto, 5 minuti, 30 minuti, 2 ore, 6 ore, 12 ore e 24 ore. Dopo l'ultimo tentativo la consegna è segnata come fallita.

Dopo 20 consegne fallite di fila spegniamo il webhook e ti avvisiamo. Lo riaccendi dalla tua area, dove vedi anche le ultime consegne con la risposta del tuo server.

Badge per il README

Ogni prodotto pubblicato ha un badge SVG che mostra quanti installatori lo portano nelle attività. Si aggiorna da solo e parla la lingua di chi lo guarda.

[![{{NOME}}](https://example.com/badge/il-tuo-progetto.svg)](https://example.com/p/il-tuo-progetto)

Lo trovi già pronto, con lo slug giusto, nella pagina del tuo prodotto e nella tua area.

Link di pagamento

Ogni installatore ha un link personale per ogni prodotto che installa. Chi lo apre trova l'installatore già scelto e può pagare con la carta o in crypto. La scelta resta ricordata per 30 giorni.

https://example.com/p/pannello-di-controllo?ref=leo-ferri-ywni

I tuoi link sono anche nella risposta di /api/v1/adozioni.

Solana Pay

Quando un'attività paga in crypto sulla rete Solana, l'ordine ha anche un link Solana Pay e il suo QR: si paga dal telefono, con qualunque wallet compatibile. Il link segue la specifica «transaction request».

solana:https%3A%2F%2Fexample.com%2Fapi%2Fsolana%2Fpay%3Fordine%3D<codice>
GET/api/solana/pay

Il wallet chiede nome e icona da mostrare.

{ "label": "{{NOME}}", "icon": "https://example.com/icona.svg" }
POST/api/solana/pay?ordine=<codice>

Il wallet manda il suo indirizzo e riceve la transazione da firmare, già divisa fra builder, installatore e piattaforma.

curl -X POST "https://example.com/api/solana/pay?ordine=<codice>" \
  -H "Content-Type: application/json" \
  -d '{ "account": "<indirizzo del wallet>" }'
{ "transaction": "<transazione in base64>", "message": "{{NOME}}: Pannello di Controllo" }

Solana Pay è attivo solo quando la piattaforma è raggiungibile in https.
